# Fecho 可靠性与工作台设计

## 目标

Fecho 的下一版先保证真实安装可运行、不同 agent 不会互相污染、扫描失败不丢数据、人工纠正不会被模型覆盖，再把 Dashboard 改造成能完成日常复核和故障诊断的工作台。系统继续保持本地优先：原始进展只进入个人 SQLite，团队 collector 只接收日报和口播稿。

验收以真实用户路径为准：从 wheel 安装后连接 Claude Code 和 Codex；两个客户端同时记录不同任务；自动扫描能从各宿主会话抽取进展；用户能在 UI 中发现低置信归属、纠正并撤销；日终报告准确反映完成、进行中和阻塞状态。任何模型、网络或格式错误都必须可见、可重试，不得静默推进水位线。

## 连接与身份

stdio 进程保留单连接上下文。HTTP 和 SSE 为每个 MCP session 建立独立上下文，包含 `session_id`、`client_name` 和认证身份；业务层不再读取进程级 `_client_name` 或 `SESSION_ID`。`log_progress` 的来源 agent 由连接上下文确定，普通调用方不能覆盖。

MCP 返回同时提供可读文本和结构化结果，至少包含 `update_id`、任务、归属方式和置信度。新增纠错、任务完成和复核工具，使 agent 不必通过“再记一条”修正错误。安装验收直接启动配置中使用的入口，避免源码可运行但安装已失效。

## 日志数据与归属

进展增加三个正交维度：`producer_agent` 表示内容由哪个宿主产生，`ingestion_method` 表示 interactive/scan/import，`completion_status` 表示 done/wip/blocked/unknown。归属保存 `assignment_source`、置信度和人工锁；人工确认是最终决定，模型只能建议修改被猜测或自动分配的记录。

主动提交严格验证日期和任务引用。未知 issue 默认拒绝并返回候选列表；自由任务通过显式 `freeform` 表达。项目绑定只在调用方没有明确指定 issue 或 freeform 时生效。

自动扫描使用适配器读取 Claude Code、Codex 和 Hermes。每个来源片段生成稳定幂等键，防止重扫创建新自由任务。模型必须返回合法结构或明确的无结果标记；格式错误属于失败，水位线停在失败片段之前。扫描运行及错误写入独立记录供 UI 查看和重试。

## 整理与状态

日报模型接收每条进展的内容类型和完成状态。确定性渲染按 Done、In Progress、Blocked 分组；缺少状态时使用 unknown，不默认判定完成。兜底稿保留原始事实并使用“今日进展”标题，避免将“尚未部署”渲染为 Done。

归属复核只处理自动或低置信记录。Mobius 缓存为空、过期或同步失败时跳过复核；已人工锁定的记录永不自动移动。验证结果单独保存指纹，输入未变化时不重复调用模型。报告指纹包含进展修订、归属、issue 标题、persona 和 prompt 版本，确保真正幂等。

任务提供完成、重开、合并和归档操作；Mobius 同步可根据远端状态更新本地任务生命周期，但不会在未授权情况下回写 Mobius。

## UI 工作台

工作台采用五个视图：Today 展示今日任务、进展和异常；Review Inbox 展示全部低置信或待确认归属；Tasks 管理任务时间线、合并和状态；Reports 展示日报、口播稿、历史版本和生成警告；System 展示 agent 连接、扫描、Mobius、LLM 和定时任务状态。

所有修改动作返回明确成功或失败反馈，并支持撤销。改变归属、恢复进展或编辑内容后，页面统一刷新统计、时间线和报告脏状态。报告不会悄悄保持旧内容：UI 显示“内容已变化，需要重新生成”。长时间线默认折叠，提供日期、任务、agent、来源和状态过滤。移动端保持核心复核操作可用。

## 错误处理与安全

数据库修改使用事务。扫描先验证再提交记录和水位线；部分失败保留可重试边界。HTTP API 检查响应状态，前端展示服务端错误。公开访问统一鉴权，健康检查不返回作者等个人信息。

测试覆盖 wheel 安装、stdio/HTTP/SSE 会话隔离、纠错与人工锁、缓存为空、无效日期和 issue、扫描格式错误、跨扫描幂等、报告状态与指纹、UI 动作后的全页面一致性。真实验收使用虚构内容调用 Mobius 和 LLM，避免污染生产日志。

## 实施顺序

1. 安装与验收可信度。
2. MCP 会话上下文与 agent 识别。
3. 提交验证、纠错和人工锁。
4. 扫描安全与多 agent 适配。
5. 日报状态、复核与幂等。
6. 任务生命周期。
7. Dashboard 后端 API 与新 UI。
8. wheel、全量测试和双 agent 真实验收。
